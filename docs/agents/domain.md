# Domain Docs

本项目采用 single-context 领域文档布局。

## 阅读顺序

开始处理任务前，按以下权威顺序读取：

1. `handoff.md`：当前阶段、已验证状态、阻塞和接手动作。
2. GitHub Roadmap #18 与相关打开 Issue：实时执行范围和验收标准。
3. `CONTEXT.md`：统一业务语言。
4. `docs/adr/`：已经确认且难以逆转的业务和架构决策。
5. 本地原始 DOCX/Excel：原始需求及数据证据；不得提交 Git 或放入镜像。
6. 当前代码：只证明当前实现，不得覆盖已确认业务规则。

## 文档布局

- 根目录 `CONTEXT.md`
- 根目录 `docs/adr/`
- 不使用 `CONTEXT-MAP.md`
- 前端与后端共享同一领域上下文

## 使用统一语言

Issue、规格、测试和代码中的领域概念应使用 `CONTEXT.md` 已定义的名称。

如果需要的概念尚未定义，应记录为待澄清问题，必要时通过 `domain-modeling` 更新 `CONTEXT.md` 或新增 ADR，不得静默创造同义词或改变数据含义。

## ADR 冲突

任何与现有 ADR 冲突的方案都必须显式指出冲突、原因和影响，并由用户决定是否重新打开该决策。

不得以当前代码行为、绿色测试或已关闭 Issue 静默覆盖 ADR。

## 证据边界

交付时区分：

- 已验证事实
- 基于代码的推断
- 尚未验证的建议

工程测试通过不等于业务验收、生产资格或发布授权。
