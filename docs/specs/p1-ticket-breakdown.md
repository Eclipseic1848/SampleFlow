## TB-01 — 共享全栈浏览器验收 fixture

## Parent

Roadmap #18

## What to build

建立一个复用的全栈浏览器验收入口，统一创建隔离 PostgreSQL、执行迁移和种子、启动 API、分配端口、收集日志并定向清理，使后续 P1 浏览器测试不再重复搭建环境。

## Acceptance criteria

- [ ] 现有浏览器测试迁移后行为不变并全部通过。
- [ ] 每个测试拥有独立数据库和端口，失败时保留最短诊断日志。
- [ ] 清理只作用于本测试明确创建的进程和数据库。
- [ ] 至少一个新增 P1 浏览器测试使用该入口。

## Blocked by

None — can start immediately.

## TB-02 — 当前月个人目标达成首页

## Parent

#10

## What to build

让业务员默认看到 `Asia/Shanghai` 当前月的个人生效目标、个人业绩、差距、达成率和自然日进度，并能从金额穿透到构成订单与不可变事件。

## Acceptance criteria

- [ ] 当前月不再由最新事件月份推断；历史月为 100% 时间进度，未来月不计算。
- [ ] 目标未生效、金额不大于零或未来月份返回稳定不计算原因，不出现除零结果。
- [ ] 汇总金额与穿透事件金额分币误差为 0，负向事件可识别。
- [ ] API 集成测试和业务员桌面 E2E 通过。

TB-01.

## TB-06 — 统一页码数据呈现

## Parent

#11

## What to build

让订单、账号、审计、分析穿透和记账治理清单使用服务端页码分页，让其他已完整加载的表格与可增长业务清单使用统一客户端分页；默认 10 条，可选 10／20／50／100 条，并支持按订单编号、客户姓名、客户单位和业务员搜索。

## Acceptance criteria

- [ ] 所有表格和可增长业务清单显示总条数、当前页／总页数、每页条数和可点击页码。
- [ ] 每页条数只允许 10、20、50、100；默认 10，切换条数或筛选后回到第 1 页。
- [ ] 订单、账号、审计和分析穿透由服务端返回当前页和精确 `totalCount`，且每次查询保持原排序与权限范围。
- [ ] 旧游标接口保持向后兼容，不与页码参数混用。
- [ ] 列表数据库读取不超过 2 次，规模增长时读取次数差不超过 1。

## TB-09 — 事件分析维度快照

## Parent

#12

## What to build

## Acceptance criteria

- [ ] 迁移故障注入证明 schema 记录、对象和数据不留半成品。
- [ ] 人工录入、事件调整和合成导入均有回归。

## TB-23 — 非 root 容器与 HTTP 安全边界

#15

## What to build
