# 受控 Excel 业绩导入

## 用户界面

销售助理和销售助理组长可在“订单业绩 → Excel 导入”下载标准模板、选择已批准配置并运行预检。预检保存文件证据、SHA-256、行级问题和对账汇总，不写正式业绩账本。

人工逐条录入必须从固定的标准业务区域中选择；大陆省级区域使用 `CN-*` 代码，“外贸”使用独立的 `EXT-TRADE` 代码且不归入任何省份。Excel 中的来源区域原文通过人事批准的精确映射转换到同一标准代码，不能由客户端提交任意代码。

导入配置把完整表头、列映射、必填字段、业务区域映射和人员映射共同保存为不可变版本。销售助理组长可以修改本人尚未批准且未产生批次的草稿；配置一旦被批准或产生导入批次，只能创建新版本，不能覆盖旧定义。

专用历史配置还必须固化 `expectedReconciliation`：整体来源行数、唯一订单数、事件数、金额，以及每个月的事件数和金额。逐月事件数、金额必须分别等于整体事件数、金额，历史配置缺少该基准时人事不能批准。预检按来源文件重新计算实际整体和逐月汇总，任一数量、月份或金额不一致都会产生批次级 `RECONCILIATION_MISMATCH` 阻断；实际值、预期值和匹配结果随批次持久化并在页面展示。

```json
{
  "expectedReconciliation": {
    "rows": 2,
    "orders": 2,
    "events": 2,
    "totalAmount": 150,
    "monthly": [
      { "month": "2026-03", "events": 1, "totalAmount": 100 },
      { "month": "2026-04", "events": 1, "totalAmount": 50 }
    ]
  }
}
```

上例仅说明字段格式，不是本项目真实迁移基准。本项目已经核验的 2026 年 1—8 月整体基准为 4,701 行、2,850 笔订单、4,701 个事件和 14,675,659.07 元；真实配置还必须从权威工作簿逐月核验并填写 1—8 月真实值，禁止根据整体值猜测或平均分摊。

标准模板只接受 `initial`。其他获批格式可以明确使用 `revenue_change`、`pause`、`restart` 和 `first_include`，并按人工录入的同一规则预演事件链：`revenue_change` 的金额表示调整后的新营业额，`first_include` 表示首次计入金额，`pause`/`restart` 的金额必须为 0。每个配置版本固化允许事件类型；已产生批次后，配置标识、版本、字段定义和审批证据均不可修改。同一订单同一天有多条事件时，配置必须映射业务顺序列，来源值从 1 开始连续且唯一；跨批次必须接续已有来源顺序，且不能在已有业务事件之前插入历史事件。缺失、重复、断号或事件状态转换非法都会阻断整批。

已关闭期间的调整行必须提供与订单、事件类型、发生日期和月份完全匹配的一次性更正授权标识。确认事务会锁定授权，并仅在事件成功入账后消费；开放期间不得携带该授权。

升级前已经存在、但没有受控批次或业务区域证据的 `legacy_adjustment`，必须重新上传原始文件核对。系统以既有来源键和行内容精确匹配，只新增不可变核对关联并按批准映射补齐订单业务区域，不修改旧事件。核对记录当前确认人；无法从来源证明的原始线下操作人明确保留为“未知”。重复核对同一事件时幂等跳过。

只有销售助理组长可确认无阻断批次；警告必须逐项确认。确认在一个数据库事务中完成，任一冲突会整批回滚。人事部批准导入配置，不逐批审批业绩数据。

完全相同的来源复合键再次导入时会作为提示自动跳过，不要求人工确认，也不会增加订单或流水。不同来源键但业务指纹相同的记录会作为疑似跨文件重复阻断。历史净额为负，或由多条流水相抵为零的订单，会逐订单产生 `HISTORICAL_REVIEW_REQUIRED` 警告；确认后仍保持“历史待核”状态，不能自动结清。

固定为 `legacy_adjustment` 的专用历史配置只改变事件语义和历史来源键规则，不绕过已关闭记账期间。首次历史迁移应在空库完成组织与业务区域映射后、首次关账前显式执行；期间关闭后的补录必须先走受控治理。

## 显式命令

本地预检：

```powershell
npm.cmd run import:preflight -- --source "D:\受控目录\来源.xlsx" --config-id "<已批准配置 ID>" --operator-user-id "<销售助理或组长用户 ID>"
```

本地确认：

```powershell
npm.cmd run import:confirm -- --batch-id "<预检批次 ID>" --operator-user-id "<销售助理组长用户 ID>" --confirm-warnings "<来源行号:警告代码,来源行号:警告代码>"
```

Compose 作业使用 `operations` profile，来源文件以只读挂载提供，不进入 Git 或镜像：

```powershell
$env:IMPORT_SOURCE_PATH = "D:\受控目录\来源.xlsx"
$env:IMPORT_CONFIG_ID = "<配置 ID>"
$env:IMPORT_OPERATOR_USER_ID = "<操作人 ID>"
docker compose --profile operations run --rm import-preflight

$env:IMPORT_BATCH_ID = "<批次 ID>"
docker compose --profile operations run --rm import-confirm
```

## 人工门禁

- 来源区域到标准业务区域的精确映射、人员来源标识映射和历史行号例外必须由业务/人事确认；“外贸”映射为 `EXT-TRADE`。
- 2026 年首次迁移的逐月对账基准必须由权威工作簿核验并由人事随配置批准；不能使用文档示例值。
- 真实 Excel 上传、正式历史入账、生产迁移和证据文件删除均需独立授权。
- 标准模板不包含任何真实业务数据；原始文件内容不输出到日志或 API 响应。
