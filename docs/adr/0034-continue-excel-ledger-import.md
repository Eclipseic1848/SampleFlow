# 沿用 Excel 正负流水追加后续业绩

用户确认：原系统已录入到 2026-08-26，后续 Excel 每行仍是一笔正负业绩流水，同一订单可以出现冲回、重录、追加。不能把这些行当作首次新订单，也不能删掉订单号重复的行。

## 2026-09-16 用户确认的体验修订（替代下文续导审批要求）

续导是系统固定能力，不再让业务用户创建配置、提交人事审批或切换账号。销售助理可以在导入窗口上传检查；销售助理组长在同一窗口补齐必要资料、核对金额、确认入账。普通自定义模板仍走原审批规则，不得把本修订扩展为取消其他审批。

前端续导不显示模板配置选择器，预检仅传 `purpose: continuation`、文件名和文件内容，不接受同时传入配置 ID 或客户端映射。后端从最新已批准的标准新订单模板取得表头及映射，移除订单号来源键、事件类型列及对应必填项，固定正负流水类型与文件来源键，且不携带旧文件固定对账基准。没有标准模板时明确报错，不猜测列名或选用任意草稿。

文件格式检查通过后才初始化系统续导规则版本；同一来源版本重复、并发检查复用同一规则。初始化写明确的 `import.continuation_rule_initialized` 审计并记录触发人和来源配置，不伪造人事审批。系统规则创建人/批准人留空，使用既有系统配置约束；旧草稿及旧批次不改写。无需迁移。预检仍不写账本，全部原有防重复、关闭期间、资料冲突和整批确认校验保留。

以下“启用与验证边界”中的手工续导审批是已被替代的历史方案；线上状态以 handoff.md 最新节为准。本次修订尚未发布，不代表真实客户文件已通过检查或已入账。

## 决策

- 复用 `legacy_adjustment` 逐行正负金额语义及现有导入事务，不推断暂停、重启或“调整后总额”。新流水关联同一订单，原事件保持不可变；已有普通业务事件的订单仍阻断，不能把两套金额口径混用。
- 保留标准新订单和固定历史文件导入配置。新增保留配置键 `excel-ledger-continuation`，专门用于持续 Excel 流水：固定 `legacy_adjustment`、启用文件哈希/工作表/原始行号来源键、禁止订单号兼作流水标识、禁止固定历史全量对账基准。
- 该例外只适用于获批续导配置。组长创建草稿、人事独立批准的权限不变；普通历史配置仍必须固化历史基准。无需数据库迁移，也不自动创建或批准真实配置。
- 每批显示实际逐月汇总，并新增必须明确确认的批次警告，说明每行金额为本次增减额。没有外部对账基准时不得宣称已与外部账本对平。
- 同文件重传复用来源键幂等跳过；改名、改行或换文件后，仍按既有指纹检查跨文件疑似重复。日期有效性、关闭期间、人员归属、客户冲突、已有普通业务事件、历史待核状态和事务内并发复检均保留。
- 不硬编码 8 月 27 日或自动剪裁文件。用户选择尚未录入的流水；发现重复候选必须核实，不静默跳过不确定记录。

## 启用与验证边界

2026-09-16 补充：现已实现界面流程（本地验证，尚未发布本次界面）。组长在 Excel 导入中选择续导用途，核对来源映射并点击“提交续导规则给人事”；不同的人事在审批中心确认并点击“批准续导规则”；组长返回导入窗口点击“刷新规则状态”，然后检查文件。复用以下配置接口，不再要求普通用户手工调用接口。提交与批准均不导入业绩，同一续导键已有草稿或已批准规则时拒绝重复创建。部署状态以 handoff.md 最新节为准。

本次只实现代码及隔离验证，不授权部署、真实配置写入或真实入账。后续发布前需确认客户继续沿用线下 Excel 作为业绩来源。

启用时通过已有 `/api/imports/configs` 创建新草稿：以实际获批“分子”表头、区域映射和人员映射为依据，保留原字段映射，但删除 `sourceRecordId` 与 `eventType` 列映射、对应必填项；设置以下字段：

```json
{
  "configKey": "excel-ledger-continuation",
  "name": "接着导入 Excel 业绩流水",
  "allowedEventTypes": ["legacy_adjustment"],
  "fixedEventType": "legacy_adjustment",
  "allowLegacySourceKey": true
}
```

这只是完整创建请求的差异字段，不能直接作为完整请求提交；不传 `expectedReconciliation`。人事通过既有批准接口确认配置后，前端续导用途才出现可选配置。原配置及已用版本不得修改；此前配置内单独绑定的来源人员关系不能跨配置自动猜测，应核对人员映射或在新批次中显式关联已有人员，不能重复创建同一人员。

上线前必须用授权的真实文件只做检查，核对来源日期、116 行/96 订单及净额 537,293.90 元是否仍与用户当前文件一致；这是此前只读调查结果，不能替代届时复验，也不意味着文件无其他业务冲突。实际入账始终由组长单独确认。
