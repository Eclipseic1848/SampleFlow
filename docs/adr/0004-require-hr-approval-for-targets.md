# 目标修改与目标确认必须由人事部审批

任何目标修改以及各级目标责任人对目标的确认，都必须经过人事部最终审批才能完成。销售经理总目标还必须先经总经理审批：销售经理依据公司确定的金额录入并签名，总经理只能批准或拒绝，不能修改金额，人事部随后执行最终审批。销售经理向业务主管下达部门目标，业务主管向业务员组长下达小组目标，业务员组长向业务员下达个人目标；主管、组长和业务员分别确认并签署本人承担的目标。责任人如提出修改申请，则由有权上级修改后交受影响责任人重新确认签名；人事部最后对最终目标版本及全部必要签名一次性批准或拒绝。只有全部必要审批完成后的最终版本才成为生效目标。人事部无权直接编辑目标数值或业绩数据。该决策加强了绩效目标的组织治理与责任留痕，代价是确认节点增多，且审批角色可能成为流程瓶颈。

## Consequences

- 待审批操作不得改变当前生效目标。
- 每次提交、批准、拒绝都必须记录操作人、时间、意见和目标版本。
- 主管、组长和业务员的签名都必须绑定各自承担的具体目标版本；本人目标金额修改后，责任人必须重新确认和签名。
- 部门、小组和个人目标的下达人、责任人签名者和人事最终审批人必须是不同人员；顶层目标的销售经理录入／签名人、总经理审批人和人事最终审批人必须是三个不同人员。
- 职责分离按稳定人员身份判断，同时拥有多个角色或更换登录账号不能兼任同一目标版本的多个步骤。
- 缺少足够不同人员时流程必须阻断，系统管理员不得代批或临时关闭规则；拒绝后创建的新版本重新执行完整检查。
- 下级目标变化但本级负责人选择不调整本级目标时，本级原签名保持有效；负责人必须完成有审计记录的目标联动选择。
- 目标责任人不能直接修改自己承担的目标。业务员向组长申请，组长向主管申请，主管向销售经理申请；直属目标下达人确定新金额，责任人重新确认签名后再提交人事部审批。
- 同一目标任一时刻只能有一条有效待处理修改申请；重复点击或网络重试必须幂等返回原申请，不得创建第二条。
- 责任人可以在直属上级处理前填写原因并撤回；拒绝必须填写意见，撤回和拒绝都保留记录，之后可以基于当前生效目标重新申请。
- 申请等待期间目标产生其他合法新版本时，旧申请自动标记为失效并禁止继续处理；接受申请后必须锁定申请并只创建一个新版本。
- 并发接受、拒绝或撤回只有第一个合法状态转换成功，其他请求必须返回明确冲突，不得生成重复目标版本。
- 人事部只进行一次最终审批，该审批同时覆盖最终目标版本和全部必要签名。
- 总经理仅承担销售经理总目标的第一道审批，不得修改目标金额；主管、组长和业务员目标均无需总经理审批或抄送。总经理审批不能替代人事部审批。
- 人事部完成最终审批前，相关责任人不能进入对应的正式业绩报表。
- 正式达成报表按个人、小组、部门和销售组织各层级目标是否生效独立门禁；下级目标未生效不阻断已经具备生效目标的上级报表。
- 目标未生效时不计算达成率或导出正式报表，但不得因此隐藏用户授权范围内的订单和不可变业绩流水。
- 高级管理身份、目标编辑权限和后台操作都不能绕过人事审批。
