# ADR-0035：当前试用库的单账号验收例外

状态：用户已批准；2026-09-17 完成实现、隔离验证、备份、迁移与当前试用环境发布。

## 决策

用户明确要求在当前真实试用系统中，由一个客户验收账号完成所有角色操作，包括提交后自行审批，不切换账号。正式服务器交付前另行清理试用数据。本次不执行数据清理。

这项要求是对目标确认、审批职责分离和记账治理人员分离规则的显式、限时验收例外，不改变普通账号规则。仅分配现有九种角色不能满足要求。

## 必须满足的边界

- 仅绑定一个不可复用的账号 ID，不能按用户名、角色组合或请求参数自动获得例外。
- 需要部署级验收开关、账号白名单和有效期；缺失、关闭或过期时拒绝例外。正式部署默认关闭，不从当前试用配置复制启用项。
- 保留登录、首次改密、CSRF、输入校验、流程状态和顺序、重复入账保护、账本与审计不可变规则。
- 允许指定账号自批及跨责任人处理验收流程，但不能伪造真实责任人确认。审计及确认文案必须明确记录验收代操作、实际账号和目标责任人。
- 数据库约束需要与后端例外一致；不能全局删除职责分离约束，也不能依赖可由客户端设置的绕过标志。
- 前端按钮、待办查询与后端授权一致。验收账号显示持续提示，注明操作真实生效。
- 不修改、重置既有客户账号；新账号通过显式运维创建并留审计。凭据仅交付给获授权负责人。

## 验收和正式交付门禁

先在隔离数据库验证：目标各层级下达、确认、修改、审批及联动；核对与关账；关闭月更正申请、批准和执行；历史核对；导入配置自批及批次确认。普通账号与其他全角色账号仍须被职责分离校验拦截。覆盖过期、开关关闭、账号停用和请求伪造。

通过后备份当前试用库，发布配套代码与迁移，再创建并验证真实验收账号；不以客户账本试写代替隔离回归。正式服务器不得启用验收开关；移除专用账号及例外配置，普通权限负例通过后才交付。
