# 一次性运维作业与 API 启动分离

API 启动或容器重启时自动执行 schema migration、管理员初始化、演示种子或历史导入，会让多副本并发、失败回滚、生产数据来源和权限边界不可控。常驻服务因此只检查前置状态并启动业务接口，所有会改变数据库结构、身份或批量业务数据的一次性操作由获授权部署人员显式执行。

## Consequences

- API 启动只检查数据库结构版本；结构缺失或落后时必须停止并提供不含机密的运维提示，不得自行迁移。
- schema migration 使用独立 `db:migrate` 作业；首个生产管理员使用 `admin:bootstrap` 作业，已有系统管理员时 bootstrap 必须拒绝重复创建。
- 历史数据使用独立预检和确认导入作业，不得在 API 启动或重启时触发。
- 开发演示数据使用显式 `dev:seed` 作业，生产环境必须拒绝执行；生产中不得创建演示账号或演示凭据。
- 每个一次性作业必须使用数据库锁防止多副本并发，重复执行必须安全拒绝或幂等跳过，并产生不包含密码或原始敏感数据的审计记录。
- Docker Compose 只定义和启动常驻服务，不隐式串联一次性作业。
- 实现这些命令不构成生产执行授权；生产迁移、bootstrap 和真实数据导入仍需分别取得人工批准。
