# 在导入窗口核对员工调组后的统计归属

2026-09-19 用户确认：张闽从2026年8月1日起归新小组，此前业绩保留原小组。导入不得因为系统登记尚未同步而无法核对调组，也不能直接取消归属校验。

## 决策与边界

- 在原有销售助理组长的导入资料核对入口，列出文件部门、小组与日期当天系统归属的差异。即使所有日期已有归属，也不能隐藏冲突项。
- 操作者必须填写实际调组生效日期，并单独确认新归属。只允许处理原文件实际出现、且不早于该生效日期的业务日期；不推断连续任职区间，不自动覆盖以后文件中的日期。
- 文件中的调组前行若写成新组，整次资料保存拒绝并提示改回原组。不自动将错误文件归属解释为调组，不改写客户原文件。
- 新增不可变 `performance_statistical_transfers`，记录人员、业务日期、生效日期、原/新部门与小组、来源批次、操作者和时间。允许后续明确核对产生新记录，不更新或删除旧证据；同一日期使用最新核对记录。重复保存相同归属不追加变更记录。
- 这是 ADR-0033 “正式任职优先”的明确例外：仅已核对调组的文件日期，统计归属优先于正式任职；没有核对记录的日期沿用旧规则。所有业绩解析入口共用同一视图。
- 正式任职、负责人、角色、目标成员与管理范围不变。新归属下的业绩按现有数据范围可见，不额外授予权限，也不伪造负责人。
- 已入账订单与事件、历史金额及归属快照不回写。历史报表不会因为此次调组自动搬组；确有历史错误必须另行核对更正。
- 对比展示时的归属版本与保存时归属，防止覆盖其他人的更新。补齐事务与整批入账共用导入锁；旧预检若引用了变化前的归属，确认时要求重新预检。
- 保存资料与入账仍是两个动作，原有金额、重复流水、关闭期间等规则保持不变。

## 发布与回退

- 新增迁移032；旧迁移和旧证据不改。须备份后协调更新API、Web并执行迁移，不支持混用旧API与新数据库。
- 迁移本身不创建任何人的调组数据，不改变没有核对记录时的解析结果。真实客户调组由具备权限的操作者确认，不由发布脚本冒充用户填写。
- 尚无新调组记录时可以在受控维护窗口恢复旧视图及迁移前版本；发布前仍须保留数据库备份。应用已有新业务后优先前向修复，不直接恢复旧备份或删记录，以免丢失客户后续操作。
- 2026-09-19经用户明确授权，已备份并完成真实验收库迁移032及API/Web更新。发布不代客户确认统计资料；完整发布证据及剩余客户文件问题见handoff.md最新发布章节。
