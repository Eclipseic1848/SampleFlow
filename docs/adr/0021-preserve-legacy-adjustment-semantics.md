# 历史 Excel 行不推断为精确业务事件

线下历史 Excel 的金额和备注不足以可靠区分暂停、重启、营业额修改或其他调整，因此历史导入统一使用 `legacy_adjustment`，不通过金额正负或关键词推断精确事件类型。每行必须原样保留正负金额、备注、文件哈希、工作表和来源行号；精确事件类型只用于 SampleFlow 上线后通过受控业务操作产生的新事件。

## Consequences

- 历史报表可以按原始正负流水还原金额，但不能把 `legacy_adjustment` 宣称为已确认的暂停、重启或营业额修改。
- 历史订单净额为正时可迁移为 `active`；只有一条零金额历史行时可迁移为 `zero`。
- 多行正负相抵为零或净额为负的订单必须标记为 `historical_review_required`，保留原始金额参与对账，并禁止暂停、重启、改额或首次计入。
- 销售助理组长记录核对结论、依据和原因，人事部批准后才可解除操作限制；核对与审批不得更新、删除或重新解释既有历史事件和金额。
- 同一历史文件重复导入必须通过稳定来源键安全跳过，不得重复记账。
- 无法解释的历史行进入异常报告，但不能因自动猜测而改变其金额或语义。
- 示例工作簿的备注分布只能作为该文件的证据，不能成为所有未来线下 Excel 的固定格式假设。
