# 保留轻流权威边界并支持受控 Excel 批量导入

轻流继续持有订单基础事实，SampleFlow 不反向修改轻流；除人工逐条表单外，系统同时支持将轻流或既有线下材料通过 Excel 批量转录。Excel 是导入传输渠道而不是第二个权威来源，ADR-0002 中“初期不支持文件导入”的限制由本 ADR 取代。

## Consequences

- 人工录入和 Excel 导入必须使用同一套服务端字段校验、业务权限、订单唯一性、组织解析和确认入账规则。
- 账号密码、角色权限、目标金额、签名和审批结果不得通过 Excel 导入。
- 系统提供标准业绩模板；每种获支持的既有线下格式使用版本化导入配置，固定工作表、表头、列映射、必填规则和省份精确映射。
- 上传时必须选择导入配置并校验实际表头；未知结构或版本不匹配必须停止预检，不能通过相似列名或内容自动猜测映射。
- 导入配置由销售助理组长创建或修改草稿，人事部批准后才能启用；创建人不能批准自己的配置。
- 已经被导入批次使用的配置版本不可覆盖修改，只能创建新版本，历史批次继续关联原版本。
- 销售助理和销售助理组长都可以上传文件、选择已批准配置并运行只读预检；预检不得写入正式账本。
- 只有销售助理组长可以确认整个导入批次正式入账；人事部只审批导入配置，不逐批审批数据。
- 每条业绩事件必须携带权威来源中的实际发生日期，记账月由系统按 `Asia/Shanghai` 自动推导；Excel 不得另行指定或覆盖记账月。
- 同一订单同一天有多条明确业务事件且没有精确时间时，来源必须提供连续、唯一的业务顺序；预检按该顺序模拟完整事件链，顺序不明或状态转换非法时阻断。
- 上传、预检和确认时间必须作为独立审计时间保存，不能代替事件发生日期；未来事件日期必须作为阻断错误。
- 尚未关闭期间的事件可以按普通批次导入；已关闭期间的事件必须先取得对应订单和事件类型的记账期间重开授权，否则阻断。首次历史迁移的 `legacy_adjustment` 使用原始历史日期。
- 任一阻断错误都会阻止整个批次确认；正式入账必须在单个事务中原子提交，数据库或并发错误导致整批回滚，不允许部分行成功。
- 预检必须一次列出全部行级错误、警告、数量和金额汇总；非阻断警告只有在销售助理组长逐项确认后才允许入账。
- 导入行应携带轻流订单编号；缺少可追溯订单编号的行必须进入异常处理，不能静默生成正式订单。
- 轻流订单编号必须作为精确文本读取并原样保存，保留前导零；不得自动去除空格、转换大小写或全角半角。
- 同一轻流订单编号始终关联同一业绩主记录；基础事实完全一致且没有新事件时作为幂等重复跳过，不得创建第二个订单。
- 相同订单编号的客户、业务员、到样日期、原始金额等基础事实发生冲突时，必须阻断整个批次并显示逐字段差异，不能通过导入覆盖。
- 同一订单的新调整必须明确提供事件类型和稳定的来源记录标识，作为新事件追加到原订单；缺少稳定来源记录标识时必须进入异常处理。
- 来源记录标识必须来自轻流或其他获批准来源，不能使用可能随文件变化的工作表行号代替；导入以来源记录标识和业务唯一键保证幂等。
- 对确实无法提供稳定来源记录编号的历史格式，人事部可以批准专用导入配置，以原始文件 SHA-256、工作表名称和原始行号组成历史来源键；该例外不得用于标准模板或能够提供稳定编号的来源。
- 历史来源键只能识别完全相同文件的重复上传；系统还必须按订单编号、日期、业务员、金额和备注识别跨文件重复候选，发现候选时阻断批次。
- 原始 Excel 不能进入 Git、应用镜像或日志；上传后必须作为不可变导入证据文件保存在受权限保护的存储中，并与导入批次、哈希和导入配置版本关联。
- v1 仅接受未加密、无密码的 `.xlsx` 工作簿，不接受 `.xls`、`.xlsb`、`.xlsm` 或 CSV。
- 系统不得执行宏、公式、外部链接或外部数据连接；映射到业务字段的单元格必须是固定值，出现公式时作为阻断错误。
- 支持 Excel 导入不授权轻流 API 接入、反向写入、生产数据导入或任何外部文件上传，这些仍需分别批准和验收。
- 历史导入必须作为 ADR-0027 定义的显式一次性作业运行，不得由 API 启动或容器重启隐式触发。
